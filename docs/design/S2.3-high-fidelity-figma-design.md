### 2.1 Color (semantic roles → candidate hex)

| Token (role) | Candidate | Notes / contrast (approx, vs stated bg) |
| --- | --- | --- |
| `color.bg` (page) | `#FBFAF8` warm paper | primary text 12.8:1 ✓ AAA |

| `color.border` (hairline) | `#E7E3DC` (on paper) / `#EAE7E1` (on white) | non-text — 1.3:1, decorative |
| `color.primary` (Trust Blue — CTA, links, active, **cart-count badge**) | `#2563B0` | white on it ≈ 5.9:1 ✓ AA (badge numeral included) |
| `color.primary.hover` / `.pressed` | `#1E4E8C` / `#173F71` | white ≈ 7.6:1 / 10:1 ✓ |

| `color.accent.tint` (a "Mới" chip / selected-state tint, always with **dark berry** text `#7A1F3D`) | `#FCEEF3` | text `#7A1F3D` ≈ 9:1 ✓ |
| `color.success` (in-stock, confirmed) | text `#177A4E` on tint `#E7F4EE` | ≈ 5.0:1 ✓ — **badge uses tint bg + dark text, not white-on-green** |
| `color.warning` | text `#8A560A` on tint `#FBF1E1` | ≈ 6.5:1 ✓ |
| `color.danger` (out-of-stock, error, blocking) | text `#B02E2E` on tint `#FBECEC` | ≈ 6.0:1 ✓ · solid `#C23B3B` + white ≈ 4.6:1 (icon/short) |
| `color.focus` (focus ring) | `#1D6FE0`, 2px ring + 2px `#FFFFFF` offset | visible on white, tint, and colored buttons |

**Restraint rules baked in:** page bg is the only large surface tint (warm paper);
blue and pink are never large fills; one primary CTA color everywhere; category tiles
share one surface tone (no rainbow).

**Badge/chip contrast rule (S2.3R):** any badge, chip, pill, or count indicator that
carries **text or a numeral** must meet **≥ 4.5:1**. Consequences: the **cart-count
badge is Trust Blue + white** (~5.9:1), not the pink accent; `StockBadge` /
`OrderStatusBadge` use a **tint bg + dark text of the same hue** (never white-on-colour);
the pink accent is used only as a *tint background with dark berry text* or as a
*non-text dot*.

## 3. Component inventory (anatomy + states)

Each is **one Figma component** with variants. Reuse-first (`visual-consistency`).
Every interactive component has: `default · hover · focus-visible · pressed · disabled`
(+ `pending` where async). Status is **never color-only** — always text and/or
icon + shape.

### 3.1 `Button`

- **Variants:** `primary` (Trust Blue fill, white text), `secondary` (white fill,
  `#1F2A37` text, `#E7E3DC` border), `ghost` (no fill/border, Trust Blue text),
  `danger-quiet` (used only for destructive confirm — `#B02E2E` text, tint bg on hover).
- **Sizes:** `lg` 48h / 16–20 px-x / `radius.sm` · `md` 40h · `sm` 36h.
- **States:** default; hover (`primary` → `#1E4E8C`; `secondary` → `#FBFAF8` fill);
  focus-visible (`color.focus` 2px ring + 2px offset); pressed (`#173F71` / inset feel);
  disabled (`#EDEBE7` fill, `#9AA1AC` text, no shadow, `cursor:not-allowed`,
  `aria-disabled`); pending (label swaps to "Đang xử lý…" + 16px spinner, disabled).
- **Full-width** variant boolean for mobile primary CTAs.
- Label: sentence case, `type.button`. Never all-caps.

### 3.2 `SearchField`

- 44h, `radius.sm`, `#FFFFFF` fill, `#E7E3DC` border, 20px search icon (leading),
  clear "✕" button (trailing, appears when non-empty, 44×44 hit area).
- Placeholder `#8A909A`: "Tìm sữa, bỉm, bình sữa…". **Visible label** (visually-hidden
  on mobile is acceptable; the icon + placeholder + `aria-label="Tìm sản phẩm"` carry
  it) — desktop shows a label or the field is clearly a search by icon + submit.
- States: default; focus (`color.focus` ring, border → `color.primary`); filled (clear
  button visible); submitting (spinner replaces search icon).

### 3.3 `TextField` / `TextArea`

- **Label above** (`type.label`, `#1F2A37`), 6px gap, field 44h (textarea min 88h),
  `radius.sm`, `#FFFFFF`, `#E7E3DC` border, 12px inner-x.
- Optional helper line below (`type.bodySm`, `#5B6673`).
- States: default; focus (`color.focus` ring + border `color.primary`); filled (value
  in `type.input` `#1F2A37`); **error** (border + ring `#C23B3B`, 16px alert icon
  leading or trailing, message below in `#B02E2E` `type.bodySm`, `aria-invalid` +
  `aria-describedby`); disabled (`#F4F2EE` fill, `#9AA1AC` text).
- Phone field: `inputmode="numeric"`, `type="tel"`, displayed grouped `09xx xxx xxx`.
- **Placeholder is never the label.**

### 3.4 `PaymentRow` (radio option, part of `PaymentMethodSelector`)

- Full-width selectable row: `radio` (left, 20px) · label (`type.h3`) · helper line
  (`type.bodySm`, `#5B6673`) · optional 20px method icon (right).
- Row: `#FFFFFF`, `#E7E3DC` border, `radius.sm`, 12–16 padding, ≥56h.
- **Selected:** border → `color.primary` (2px), radio filled, subtle `color.primary.tint`
  fill, a 16px check — **three signals, not color alone**.
- Focus-visible ring on the row. Disabled during submit (`#F4F2EE`).
- Two instances: "Thanh toán khi nhận hàng (COD)" / "Chuyển khoản ngân hàng".

### 3.5 `Price`

- One VND format everywhere: `315.000 ₫` (thousands `.`, non-breaking space before
  `₫`). `type.price.*` per context, `tabular-nums`, `#1F2A37`.
- Boolean `strikethrough` (muted `#8A909A`, for the old price in a price-changed line).
- No decimals ever. Integer VND.

### 3.6 `StockBadge`

- Chip: 16px icon + `type.label` text, `radius.xs`, 4/8 padding.
- **In stock:** `#E7F4EE` bg, `#177A4E` text, check-circle icon, "Còn hàng". *(May be
  omitted on `ProductCard` when in stock if S2.4 prefers; always shown on PDP.)*
- **Out of stock:** `#FBECEC` bg, `#B02E2E` text, slash-circle icon, "Hết hàng".
- Never a number. Never "Sắp hết hàng".

### 3.7 `QuantitySelector`

- `[ − ]  [ 2 ]  [ + ]` — each button 44×44, `radius.sm`, `#FFFFFF`, `#E7E3DC` border;
  value 44w center, `type.h3`, `tabular`.
- `aria-label` "Giảm số lượng" / "Tăng số lượng"; value is a labelled `input` /
  `spinbutton`.
- States: default; `−` disabled at min 1; `+` disabled at UX max (with a tooltip/inline
  "Tối đa N"); whole control disabled when out of stock; focus ring per button.

### 3.8 `AddToCartButton`

- `Button` `primary` `lg` `full-width`, label "Thêm vào giỏ", leading 20px cart-plus
  icon.
- **Out of stock:** disabled, label "Hết hàng", no icon (or a slash icon). Still looks
  like a button, clearly inactive.
- **Pending:** "Đang thêm…" + spinner.
- On success: fires a `Toast` ("Đã thêm vào giỏ" + "Xem giỏ hàng" link) and the header
  cart count updates; an `aria-live="polite"` region announces it.

### 3.9 `ProductCard` — the reusability anchor

**One component. No Add-to-Cart. Whole card is a link to `/san-pham/[slug]`.**

Anatomy (top→bottom), card = `#FFFFFF`, `radius.sm`, `#EAE7E1` hairline border, `elevation.flat`, 12px inner padding:

1. **Image frame** — square 1:1, `#F4F2EE` bg, `radius.md`, image `object-fit: contain`
   with ~10% internal padding. One image only. Never crops label text.
2. **Brand** — `type.caption` `#5B6673`, 1 line, uppercase-tracking optional.
3. **Name** — `type.productName.card`, `#1F2A37`, **2-line clamp, reserved 40px height**
   so price/stock never shift between cards.
4. **Unit** — `type.caption` `#5B6673`, only when meaningful ("Lon 800g").
5. **Price** — `type.price.card`, `#1F2A37` — the loudest text after the image.
6. **StockBadge** — only rendered as "Hết hàng" (in-stock badge omitted on the card to
   reduce noise; S2.4 may re-add).

**Variants / states:** `default` · `hover` (desktop: `elevation.raise` + border →
`#D8D3CA`, image scales 1.02 with `prefers-reduced-motion` guard) · `focus-visible`
(`color.focus` 2px ring around the whole card, 2px offset) · `out-of-stock` (full
colour + legible; "Hết hàng" badge overlaid on the image bottom-left; image at 92%
opacity max) · `missing-image` (see 3.18) · `long-name` (2-line clamp + ellipsis, no
layout shift).

Card min-width at 390 (2-up, 16 gutter, 12 gap) ≈ **171px**; image ≈ 147px square.

### 3.14 `CartLineItem`

### 3.19 `CheckoutSubmitButton`

`Button primary lg full-width`. States: `idle-enabled` ("Đặt hàng") · `idle-disabled`
(form invalid — still shows, press reveals errors + moves focus) · `revalidating`
("Đang kiểm tra giỏ hàng…" + spinner, disabled) · `submitting` ("Đang xử lý…" + spinner,
disabled, form dims to read-only) · `blocked` ("Xác nhận & đặt hàng" after a

## 6. Accessibility decisions (built into the design)

- **Focus-visible** designed for: `Button` (all variants), `ProductCard` (ring around
  the whole card), `SearchField`, `TextField`/`TextArea`, `PaymentRow`,
  `QuantitySelector` (+/− and value), cart remove ✕, pagination links, breadcrumb links,
  hamburger, drawer close. Ring = `#1D6FE0` 2px + 2px `#FFFFFF` offset — visible on
  white, `#F4F2EE`, and on the Trust Blue button.
- **Status is never color-only:** `StockBadge` (icon + text), `OrderStatusBadge` (icon +
  text), `CartLineItem` change states (left-border **+** icon **+** text label),
  `PaymentRow` selected (border **+** radio **+** check **+** tint), field error (icon
  **+** border **+** message text). Price change: strikethrough **+** "Giá đã thay đổi"
  text, not just colour.
- **Labels visible** on every field (label above, never placeholder-as-label). Icon-only
  buttons carry `aria-label` in Vietnamese (cart, close, remove "Xoá {name} khỏi giỏ",
  qty +/−).
- **Form errors** associated (`aria-invalid` + `aria-describedby`); submit-time summary
  moves focus to the first invalid field.
- **Dialogs / drawers / sheets** (cart drawer, filter sheet, image enlarge, nav drawer):
  focus in → trap → `Esc` / scrim → focus returns to trigger.
- **Contrast:** all body/price/label/helper combos in §2.1 hit AA (most AAA). The two
  to re-verify at S2.4 with final values: the pink cart-badge numeral (`~4.0:1` — OK
  for ≤2 digits, fallback Trust Blue) and any white-on-`color.primary` small text
  (`5.9:1` — fine for `type.button`).
- **Touch targets** ≥ 44×44: qty +/−, remove, filter/sort buttons, pagination, nav,
  close, copy buttons.
- **Reduced motion:** `ProductCard` hover scale, gallery cross-fade, drawer/sheet
  slide, toast — all gated by `prefers-reduced-motion` (S1 already ships the global CSS
  block). No motion conveys state.
- **One `<h1>` per screen** (Home = the hero heading; PDP = the product name; Catalog =
  "Sản phẩm" / "Kết quả cho …"; etc.). No skipped heading levels.
- **No hover-only** discovery: gallery zoom, menus, tooltips all have tap/keyboard
  equivalents.

### 13.2 Correction — cart-badge contrast

The S2.3 token note allowed the pink accent `#D64C7C` behind the white cart-count
numeral at **~4.0:1**, "OK for a ≤2-digit numeral". **That is wrong** — a badge that
carries text or a numeral is normal text and must meet **≥ 4.5:1**.

**Corrected principle (now in §2.1):** any badge / chip / pill / count indicator with
text or a numeral must meet **≥ 4.5:1**. Options weighed: (A) darker pink + white — pushes
the hue toward berry/maroon, loses the "warm pink" character; (B) dark berry text on a
light pink tint — weak as a *count* indicator (a solid dot reads better); (C) **Trust
Blue badge + white** — 5.9:1, coherent with the structural anchor, unambiguous as a
count.

**Chosen: C.** The cart-count badge is **`color.primary` `#2563B0` + white**. Pink is
demoted to *tint-background-with-dark-berry-text* (e.g. a "Mới" chip, ~9:1) or a
*non-text dot* only. Applied in all 6 canvas artboards that show the header, and on the
`Foundations` board (swatch labels + a new "contrast rule" note). **Exact final hues
remain S2.4's to sample from the brand asset.**

### 13.6 360px stress-test result

The mock artboards are **fixed 390px** frames, so at a 360px viewport the frame simply
**overflows** (visible in the 360 render: the header cart icon and the grid's right
column are clipped). This is a *mock* artefact, not a design failure — the real layout
is fluid. What it tells the fluid implementation:

- At 360px, usable width ≈ **328px** (16px gutters). A 2-col grid with a 12px gap →
  **158px per card**, ~134px image. **Tight but workable** — name (2-line clamp), price
  (15/700), and image remain legible.
- **Responsive proposal (small, not a system change):** below ~375px, reduce the outer
  gutter to **12** and the card gap to **10** (→ ~163px card); keep the 2-line name
  clamp; allow `type.productName.card` to step to **13.5px** under 360. **Do not** drop
  to 1-column (wastes scan density for a catalog of similar SKUs).
- **Header at 360:** the top row (hamburger · logo · cart) has little slack — allow the
  logo wordmark to shrink one step; the full-width search row is unaffected.
- **Product Detail / Cart / Checkout / payment rows / sticky bar at 360:** single-column
  already; they reflow without change. `QuantitySelector` (44px controls) fits.
