# S2.5 — Design System Implementation

**Phase:** S2.5 — Design System Implementation. **Status: DONE.**

This document is a short **implementation reference** — where tokens live, how they
map to Tailwind v4, where shared primitives live, and what is prohibited. It does
**not** restate token values. The single source of truth for every value remains
[`S2.4-design-system-and-approval.md`](S2.4-design-system-and-approval.md) ("the S2.4
doc"). If this document and the S2.4 doc ever disagree on a value, **the S2.4 doc
wins** — fix this document, not the frozen tokens.

## 1. Where tokens live

**`src/app/globals.css`** is the *only* place a design-token value is declared:

- **Colour / radius / shadow / font family / container width** — a Tailwind v4
  `@theme` block. Each `--color-*` / `--radius-*` / `--shadow-*` / `--container-*`
  entry is copied verbatim from the S2.4 doc §4/§7/§9 and generates the matching
  utility (`bg-primary`, `text-text-muted`, `rounded-sm`, `shadow-overlay`,
  `max-w-content`, …), exactly as S2.4 §17.1 specifies.
- **Spacing** — no override. Tailwind v4's *default* 4px spacing scale
  (`--spacing: 0.25rem`) already equals the frozen S2.4 §6 base scale; see the
  mapping table in the `globals.css` comment.
- **Breakpoints** — no override for `md`/`lg`/`xl` (768/1024/1280 already match
  Tailwind's defaults). The frozen **≤374px compact-mobile** tier (S2.4 §6) is a
  max-width case Tailwind's min-width scale can't express, so it's a custom
  `@custom-variant compact (@media (max-width: 374px))` — use it as `compact:gap-2.5`,
  `compact:px-3`, etc.

  **Note:** the S2.5 phase brief also named a `480px` breakpoint. The S2.4 doc (the
  authoritative document, per its own source-of-truth hierarchy, §18) does **not**
  define one — only ≤767 / 768–1023 / ≥1024, plus the ≤374px compact tier. No `480px`
  breakpoint was added; inventing one not in S2.4 would itself be a token addition
  requiring the same governance as changing one. Flagged here rather than resolved
  silently — see the completion report.
- **Typography roles** (S2.4 §5) — implemented as compound `@layer components`
  classes (`.text-h1`, `.text-price-lg`, …), not bare `--text-*` theme tokens. Each
  role bundles size + line-height + weight + (for price roles) tabular numerals, and
  four roles change value at the desktop breakpoint — a single flat token→utility
  mapping can't express that compound, breakpoint-conditional shape. One class name
  == one frozen role; see the comment above that block in `globals.css` for the full
  reasoning.
- **`docs/` and `.claude/skills/` are excluded from Tailwind's class scanner**
  (`@source not`) — those files quote anti-pattern examples like `bg-[#2563B0]`
  verbatim (S2.4 §17.1, the design-system/figma-to-code skills), and without the
  exclusion Tailwind's automatic content detection compiled those quoted examples
  into real (unused) utility classes in the production CSS.

**Light-only MVP (S2.4 §16):** the S1 scaffold's `prefers-color-scheme: dark` block
is removed. There is no dark theme, no toggle, and no `dark:` variant anywhere in
`src/`.

## 2. Shared primitives

```
src/lib/utils.ts                    cn() — clsx + tailwind-merge
src/components/ui/                  shadcn-style primitives (Radix + CVA), themed
  button.tsx           Button (primary / secondary / ghost; lg/md/sm)
  input.tsx            Input
  textarea.tsx          Textarea
  label.tsx             Label (Radix)
  form-field.tsx        FormField — visible label + associated error (S2.4 §14/§15)
  radio-group.tsx       RadioGroup / RadioGroupItem (Radix) — for a future PaymentRow
  badge.tsx             Badge — tint + text status foundation (S2.4 §4.1/§14)
  skeleton.tsx          Skeleton
  separator.tsx         Separator (Radix)
  dialog.tsx            Dialog (Radix) — centered modal
  sheet.tsx             Sheet (Radix Dialog, edge-anchored: bottom / right)
src/components/layout/              generic layout, no commerce content
  container.tsx         Container — 1200px content width + frozen gutters
  stack.tsx             Stack — flex row/col with a token-scale gap
  grid.tsx              Grid — variant="catalog" is the frozen 2/3/4-col grid
  section-heading.tsx   SectionHeading
  empty-state.tsx       EmptyState
  error-state.tsx       ErrorState
src/components/site/                structural, presentational only
  header.tsx            Header — frozen heights/sticky/slots, no real nav wiring
  cart-indicator.tsx    CartIndicator — the frozen primary+white cart badge
```

**Not built in S2.5** (commerce scope, S3+): `ProductCard`, `PaymentRow`,
`CategoryTile`, `StockBadge`/`OrderStatusBadge` label wiring, any Supabase-backed
component. `Grid`/`Header`/`Badge` establish the primitives those will need without
inventing the components themselves (S2.5 brief §21).

## 3. shadcn/ui mapping

No `shadcn` CLI / `components.json` was initialized. The primitives above follow the
same pattern shadcn generates (a local, owned copy of Radix + CVA code in
`src/components/ui`, not an installed package) so they can be regenerated or extended
with the CLI later without changing this structure — but every visual value already
comes from the S2.4 tokens, never an unstyled Radix/shadcn default.

## 4. Consuming the design system

- Never write a raw hex, px, or arbitrary Tailwind bracket value in a component. If a
  needed value doesn't exist as a token/role, that is a **Design Deviation Proposal**
  (S2.4 §19), not a one-off `bg-[#...]` or `p-[13px]`.
- Reuse a primitive from `src/components/ui` or `src/components/layout`; do not create
  a second `Button`/`Container`/`Input`.
- Icons: `lucide-react` only (installed this phase). No emoji, no second icon package.

## 5. Prohibited (unchanged from S2.4 §19)

Primary colour, accent use, type scale, radius/shadow language, the 1200px container,
`ProductCard`, the header system, the checkout model, mobile navigation, and
primary-CTA hierarchy stay frozen. A real implementation problem is raised as a
Design Deviation Proposal, not patched silently.
