**Phase:** S2.4 — Design System & Design Approval. **Status: DESIGN APPROVED (V1).**
This document **freezes** the Baby Wale storefront design system — tokens, component
design contracts, responsive behavior, accessibility rules, and content-claim rules —
as the visual contract for implementation (S3+).

**Date:** 2026-09-12. **Depends on:** S0, S2.1, S2.2, S2.3, S2.3R.

**Direction:** **Soft Trust Commerce** (locked at S2.2, unchanged). No B/C alternate
was revisited.

**This document is now the authority.** Where it conflicts with S2.1 / S2.2 / S2.3 /
S2.3R wording, **S2.4 wins** (§18). Those documents remain valid as evidence, anatomy
detail, and screen specification for anything not restated here.

**What changes after this document:** implementation (S2.5+) may **compose** the
frozen tokens and components. It may **not** casually change primary colour, accent
use, type scale, radius language, shadow language, container, `ProductCard`, the
header system, the checkout visual model, mobile navigation, or primary-CTA hierarchy
(§19 — Design Change Governance).

## 2. Visual review decisions incorporated

Five corrections resolved before freeze (all confirmed against the S2.3R canvas/spec):

### 2.1 Mobile Catalog control wrapping

**Problem:** at 390px, "Danh mục" and "Sắp xếp: Mới nhất" triggers could wrap across
lines.

**Frozen rule:** the two catalog toolbar triggers are **one line each, never wrap**, at
≥44px touch height, and both fit side by side at 390px.

- Trigger labels (mobile): **"Danh mục"** and **"Mới nhất"** (the current sort's short
  label only — not "Sắp xếp: Mới nhất").
- The **sheet title** (opened by the sort trigger) may say the fuller **"Sắp xếp sản
  phẩm"** — verbosity belongs in the sheet, not the trigger.
- Desktop may use a more descriptive inline label (e.g. a labelled dropdown reading
  "Sắp xếp: Mới nhất") since desktop has width to spare — this rule is **mobile-only**.
- Trigger sizing: `height: 40`, horizontal padding enough for the label + chevron
  without wrap; if a category name is long, truncate with an ellipsis inside the
  trigger, never wrap.

### 2.2 Horizontal product-rail scrollbar

**Problem:** the rendered Home / Product Detail rails showed the native horizontal
scrollbar — not part of the intended visual language.

**Frozen rule:** horizontal product rails (Home "Sản phẩm mới", PDP "Sản phẩm liên
quan") **keep native scroll semantics** — touch swipe, trackpad/wheel, and keyboard
where applicable all keep working — but the **scrollbar is visually hidden** (e.g.
`scrollbar-width: none` + the WebKit scrollbar-hiding pseudo-selector; never
`overflow: hidden`, which would kill scrolling). A **partial next card** stays visible
at the trailing edge as a discoverability cue. **No fake auto-moving carousel** — the
rail only moves on user input. **Desktop converts to a normal grid** wherever the
spec already calls for a grid (Catalog, Category, PDP related when width allows);
Home's "Sản phẩm mới" and PDP's "related" rails are the two places a **mobile
horizontal rail is approved**.

### 2.3 ProductCard consistency (Home rail vs Catalog grid)

**Problem:** the Home rail rendered `ProductCard` narrower than the Catalog grid card.

**Frozen rule:** **one `ProductCard` anatomy** everywhere (§10.1). The **container**
(grid cell vs rail item) may determine the card's width, but image ratio, internal
padding, typography hierarchy, name clamp, price hierarchy, radius, and state treatment
**never change** between contexts. **Safe minimum mobile card width: 160–171px**
(matches the approved 2-column 390px grid math, §9). A rail card must not shrink below
this — if a rail context would force a narrower card, widen the rail item instead of
shrinking the card. **At ~390px, the Catalog 2-column grid remains approved** (§9).

### 2.4 Unverified "Giao hàng toàn quốc" claim

**Problem:** some rendered trust rows stated **"Giao hàng toàn quốc"** — a shipping-
coverage claim never approved by the owner.

**Frozen rule:** **removed as a production statement.** It is **not** replaced with any
other delivery-coverage or delivery-speed claim. Until the owner supplies a real
shipping/coverage policy, trust copy is limited to the **approved factual set** (§15):
"Thanh toán khi nhận hàng (COD) hoặc chuyển khoản", "Nhân viên xác nhận từng đơn trước
khi xử lý", "Hỗ trợ: [OWNER CONTENT TBD]". A future owner-provided shipping policy may
add geographic-coverage wording **as a content update**, not a design-system change.

**Applied, not just documented:** the phrase was removed from all four canvas
artboards that rendered it (`Home`, `Main`, `ProductDetailDesktop`, `Components`),
replaced with the approved COD/transfer line, and the canvas republished as **v4**
(§21 / link below) — the visual evidence now matches this rule.

### 2.5 Product image frame — approved for V1, with a validation checkpoint

**No real Baby Wale product photography exists.** For **DESIGN SYSTEM V1**, the
**1:1 `contain` frame + internal breathing room + neutral subtle surface** is
**approved as the default** (§11) — it supports formula cans, diaper packages (tall and
wide), bottles, wipes, and mixed supplier photography without cropping labels, and
works consistently in the 2-column mobile catalog.

**Mandatory checkpoint (recorded, not a blocker):** **before S4 visual sign-off**,
validate the frame against **5–6 real storefront-safe images** spanning: formula can/
box, tall diaper package, wide diaper package, bottle, wipes, and one more irregular
package. **If 4:5 proves materially better**, changing the image-frame aspect ratio
requires an explicit visual review (§19) — it is a global token change, not a per-page
tweak. **S2.4 is not blocked by the absence of real imagery today.**

## 3. Final visual doctrine

Unchanged from S2.2/S2.3, now frozen as policy:

> Baby Wale should feel like a real, caring mother-and-baby shop that is also visibly
> competent to take an order — calm, clean, warm, quietly friendly, trustworthy. The
> page prioritizes the product (photo, name, price, availability) and the one primary
> action before any decoration. Surfaces are light and soft; structure comes from
> space, tone, and hairline borders before shadow. **Blue is the structural trust
> anchor** (primary action, links, key accents); **pink is a small warmth accent**
> (never a large fill, never behind small text). Product photography carries the
> commercial content. Typography is humanist, highly legible at mobile sizes, and
> excellent for Vietnamese diacritics. CTAs are calm and singular — no caps, no
> pulsing, no urgency language. Trust information is quiet and **factual only**.
> Mobile (~390px) is the primary canvas.

**Never** (unchanged, now binding): pink/blue as page backgrounds; pastel-on-pastel low
contrast; a giant gradient hero; a rotating carousel as the hero; pill/blob shapes as
default; a shadow on every card; per-page radius/shadow/type drift; decorative blobs;
more than one primary CTA colour; marketplace-tiny type; hover-only behaviour; emoji as
the icon system; images cropped through label text; a checkout styled as a marketing
page; fabricated social proof or claims; a visual language that changes page to page.

### 4.1 Contrast verification (recalculated, WCAG 2.1 relative-luminance formula)

| Pair | Ratio | AA normal text (≥4.5:1) | AA large/UI (≥3:1) |
| --- | --- | --- | --- |
| `--color-text` on `--color-bg` | **13.94:1** | ✅ | ✅ |
| `--color-text` on `--color-surface` | **14.54:1** | ✅ | ✅ |
| `--color-text-muted` on `--color-bg` | **5.60:1** | ✅ | ✅ |
| `--color-text-muted` on `--color-surface` | **5.84:1** | ✅ | ✅ |
| white on `--color-primary` (buttons, cart badge) | **6.02:1** | ✅ | ✅ |
| white on `--color-primary-hover` | **8.32:1** | ✅ | ✅ |
| white on `--color-primary-pressed` | **10.57:1** | ✅ | ✅ |
| `--color-text` on `--color-primary-tint` | **12.87:1** | ✅ | ✅ |
| `--color-primary` text (links/ghost buttons) on `--color-bg` | **5.77:1** | ✅ | ✅ |
| `--color-primary` text on `--color-surface` | **6.02:1** | ✅ | ✅ |
| `--color-accent-text` on `--color-accent-tint` | **8.93:1** | ✅ | ✅ |
| **white on `--color-accent` (REJECTED for text)** | **4.05:1** | ❌ | ✅ (non-text only) |
| `--color-success` on `--color-success-bg` | **4.73:1** | ✅ (passes; narrow margin) | ✅ |
| `--color-warning` on `--color-warning-bg` | **5.49:1** | ✅ | ✅ |
| `--color-danger` on `--color-danger-bg` | **5.59:1** | ✅ | ✅ |
| `--color-focus` on `--color-surface` (non-text indicator) | **4.77:1** | — | ✅ (≥3:1 required) |
| `--color-focus` on `--color-bg` | **4.57:1** | — | ✅ |
| Muted placeholder `#8A909A` on `--color-surface` | 3.21:1 | ❌ | — |

**Frozen consequences:**

- **Badge/chip/pill contrast rule:** any badge, chip, pill, or count indicator that
  carries **text or a numeral** must meet **≥ 4.5:1**. `--color-accent` **fails** this
  and is **never** used as a fill behind text or a numeral (this rejects the earlier
  4.0:1 cart-badge implementation for good). The **cart-count badge is
  `--color-primary` + white** (6.02:1).
- `StockBadge` / `OrderStatusBadge` use **tint background + matching dark text**
  (never a solid colour fill with white text) — `--color-success` on
  `--color-success-bg`, etc.
- **Placeholder text is decorative only** (3.21:1, fails AA) — it is **never** the
  accessible name or the only cue for a field's purpose; every field has a **visible
  label above it** (§14).
- Focus ring `--color-focus` clears the ≥3:1 non-text-indicator requirement against
  both `--color-surface` and `--color-bg`.

### 4.2 Restraint rules (frozen)

Page background is the **only** large surface tint. Blue and pink are **never** large
fills. **One** primary CTA colour, everywhere, always. Category tiles share **one**
surface tone — no rainbow.

- **Price hierarchy is fixed**: `--type-price-large` > `--type-price-total` >
  `--type-price-card`, and price is always the loudest text after the product image.

## 6. Final spacing & grid

**Base scale (frozen):** `2, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64` (px). No arbitrary
one-off values (`13px`, `17px`, `27px`, …) without a stated technical geometry reason
(e.g. a 44px control minus a 1px border).

| Context | Normal | Compact (**≤374px**) |
| --- | --- | --- |
| Mobile outer gutter | **16** | **12** |
| Mobile product-grid gap | **12** (col) / 20 (row) | **10** (col) — row gap unchanged |
| Card inner padding | 12 | 12 |
| Form field-to-field gap | 16 | 16 |
| Mobile section rhythm (between page sections) | 32 | 32 |
| Desktop page gutter | 24–32 | — |
| Desktop section rhythm | 48–64 | — |

**Compact-mobile adaptation (≤374px) is frozen as:**

- **12px** outer gutter, **~10px** `ProductGrid` gap.
- **Maintain 2 columns** — do **not** auto-switch to 1 column at small widths.
- Logo wordmark **may shrink one step**; the full-width search row is unaffected.
- **Card text stays at the normal type scale** (`--type-product-name-card` = **14px**,
  unchanged) — the proposed 13.5px step-down from S2.3R is **not** adopted; the S2.3R
  measurement (~158–163px card at 360px) showed 14px still fits. Revisit only if a real
  device test shows genuine clipping.

## 9. Final responsive rules

### 9.1 Breakpoints & grid (frozen)

| Breakpoint | Value | Product grid |
| --- | --- | --- |
| Mobile | ≤767 (compact ≤374, §6) | **2 columns** |
| `md` | 768–1023 | **3 columns** |

Desktop content **max-width 1200px**, 24–32px gutters. **Do not** use the full 1440px
viewport width for normal product content (1440 is only the *canvas artboard* frame,
not the content width).

### 9.2 Sticky model (frozen, no exceptions)

**One compact persistent top header, plus at most one bottom transactional sticky
surface.**

| Screen | Top | Bottom |
| --- | --- | --- |
| Product Detail (mobile) | header (104) | Add-to-Cart bar (64) |
| Cart (mobile) | header (104) | Checkout bar (64) |
| Checkout (mobile) | slim header (56) | **none — submit stays in-flow** |
| Everywhere else | header | none |

**Never:** a bottom navigation bar (there is no bottom nav in this system — mobile
navigation is header + hamburger, per S2.1, unchanged); two stacked bottom sticky bars;
a sticky filter/sort bar together with a sticky transactional bar; sticky UI that
occupies excessive viewport height.

### 9.3 Horizontal rail rule (frozen, §2.2)

Home "Sản phẩm mới" and PDP "Sản phẩm liên quan" may scroll horizontally on mobile:
native scroll + touch/wheel/keyboard preserved, **visual scrollbar hidden**, **no
auto-rotation**, a **partial next card** visible as a cue, **same `ProductCard`** at
its approved minimum width. Desktop converts to a grid wherever the spec calls for one.

## 10. Final component design contracts

Anatomy detail beyond what's restated here stays in S2.3 §3 (unchanged unless noted).
**S2.4 freezes the contract; S2.3 keeps the anatomy reference.**

### 10.1 `ProductCard` — frozen design contract

- **One component**, reused unchanged across Home, Catalog, Category, Search, Related,
  and rail contexts (§2.3). Container width may vary; the card does not.
- **No Add-to-Cart in MVP.** The whole card is a link to Product Detail.
- **One image**, **1:1**, `object-fit: contain`, on `--color-surface-subtle`,
  `--radius-md`, with internal breathing room. **No thumbnails on any card.**
- Content order: image → brand (quiet) → name (2-line clamp, reserved height) →
  optional unit (only when meaningful) → price (loudest text after the image) →
  **out-of-stock badge only when out of stock** (no "in stock" badge on listing cards).
- **No channel prices** (`tiktok_price`/`shopee_price` — never shown, per
  `public-data-contract`). **No discount UI** (no MVP coupon/promo system).
- **No heavy shadow** — `--elevation-flat` at rest.
- **Safe minimum mobile width: 160–171px** (§2.3).
- **States (frozen):** `default` · `hover` (desktop: `--elevation-raise` + border
  shift, respects `prefers-reduced-motion`) · `focus-visible` (ring around the whole
  card) · `long-name` (clamp, no shift) · `out-of-stock` (full colour, legible, badge
  visible, no greying-to-invisibility) · `missing-image` (the neutral placeholder
  frame, §11).

### 10.2 `Header` / `MobileHeader` — frozen

- Desktop 64px, mobile 104px (56 top row + 48 search row), both **sticky**.
- Mobile top row: hamburger · logo · cart+badge. Search is a **full-width row**,
  always visible — never hidden behind an icon.
- Desktop: logo · "Sản phẩm" + "Danh mục" nav · centered `SearchField` · quiet "Tra cứu
  đơn hàng" link · cart+badge.
- **No login/account entry** (guest MVP).
- Cart badge: `--color-primary` + white (§4.1).

### 10.3 Product Detail — frozen north-star contract

**Mobile hierarchy (frozen, top→bottom):** breadcrumb → gallery → name → brand → price
→ stock → unit → quantity → Add-to-Cart → trust → description → specification →
related products. **Desktop:** gallery left, purchase block right (may be sticky),
description/specs below, related products below that.

- **Sticky Add-to-Cart bar appears only after the in-flow CTA scrolls out of view** —
  never two active Add-to-Cart affordances visible at once.
- Gallery: **1:1 V1 frame**, `contain`, no package cropping. **Thumbnails: Product
  Detail only** (never on a listing card), shown **only when multiple images exist**.
  Image-enlarge affordance is allowed.
- OOS variant: price still shown, `StockBadge` = "Hết hàng", Add-to-Cart disabled and
  labelled "Hết hàng" (not hidden), quantity disabled, related products get more
  presence, full description/specs stay readable.

### 10.4 Cart — frozen contract

- Compact `CartLineItem` structure (image, name, unit, qty, remove, line total).
- **Price increase requires explicit customer acknowledgement** — never silently
  charged; shown with the **informational** (blue-tint) treatment, not red.
- **Stock-adjustment** uses the **warning** (amber-tint) treatment with an explicit
  "Cập nhật số lượng còn N" action — never auto-reduced.
- **OOS / unavailable** lines use the danger tint with a "Xoá" action.
- **No whole-page red treatment** for any recoverable state.
- Totals terminology: **"Tạm tính (hàng hoá)"**, **"Phí vận chuyển: Nhân viên sẽ xác
  nhận"** (plain text, not a warning style), **"Tổng tiền hàng"** (never "Tổng thanh
  toán" while shipping is unresolved — CLAUDE.md §8).
- **Sticky mobile Checkout CTA** (§9.2). **Cart survives recoverable errors** — never
  cleared except after a committed order.

### 10.5 Checkout — frozen "trust test" contract

- **Single page.** Mobile: slim header (no commerce nav/cart/search) → collapsed order
  summary → contact/shipping fields → payment method → review → shipping notice →
  **submit in-flow (no sticky bottom bar)** → quiet trust cues.
- **No** recommendations, marketing banners, or cross-sell anywhere in checkout.
- Desktop: form left, **sticky order summary right**.
- **Checkout is the standing "trust test"** for every future design change — any

### 10.6 `PaymentRow` — frozen

Selected state = **border + radio + tint + check** — never colour alone. MVP methods:
**COD** and **bank transfer** only. **No fake payment-success state** anywhere in the
flow.

### 10.7 Success / Tracking — frozen

- **Primary utility: "Sao chép liên kết theo dõi".** **Secondary: "Tiếp tục mua sắm".**
  **Never** a "Theo dõi đơn hàng" button linking to the page's own URL.

## 11. Product image contract

**V1 (frozen, §2.5):** every product image — `ProductCard`, PDP gallery main + thumbs,
related, rail — uses **one square (1:1) frame**, `object-fit: contain`, ~10% internal
padding, on `--color-surface-subtle`, `--radius-md`. Labels/packaging text are never
cropped. Source images are never recoloured or altered — the frame normalizes varied
supplier photography.

**Missing-image state:** the identical neutral frame + a subtle whale/box line motif +
the product name below. **Never** a broken-image glyph, a stock photo, or a fabricated
render.

**Mandatory validation checkpoint before S4 sign-off:** test against 5–6 real
storefront-safe images (formula can/box, tall diaper pack, wide diaper pack, bottle,
wipes, one more irregular package). A move to 4:5 is possible but requires the §19
governance process — it is a global token change.

## 12. Icon & illustration strategy

**Direction (decided, not installed):** **Lucide React** for standard interface icons
— menu, search, cart, chevron, copy, trash, plus/minus, alert/status, check, close,
phone, delivery/support glyphs where appropriate. One consistent stroke-based family;
never mixed with another icon pack; never emoji as the production icon system.

**Category-specific pictograms** (diaper, bottle, formula/milk, …) that Lucide doesn't
cover: **small custom project SVGs are allowed**, drawn to match Lucide's stroke
weight, corner character, viewBox sizing, and visual weight — one coherent set, not a
second visual language.

**Not installed in S2.4** — this is a direction decision for **S2.5** to implement.

## 13. Motion contract

Motion is **supporting feedback only**. **Allowed:** short hover/focus transitions,
drawer/sheet open-close, toast appearance, quantity/cart micro-feedback, small state
transitions (~150–250ms feel). **Avoid:** hero animation, autoplay, parallax, floating
decoration, continuous/looping motion. **`prefers-reduced-motion` is always
respected** — no information is conveyed only through motion. No animation library.

## 14. Accessibility contract

Frozen as a hard requirement for every component and screen:

- **WCAG AA text contrast** (§4.1) — including the **≥4.5:1 rule for any badge/chip/
  pill carrying text or a numeral**.
- **Visible focus** — `--color-focus` ring, 2px + 2px offset, on every interactive
  element; never removed without a stronger replacement.
- **≥44×44px** for every critical touch target.
- **Labels above every field**, always visible — placeholder text is decorative only
  (§4.1), never the accessible name.
- **Errors: text + visual cue**, associated with the field (`aria-invalid` +
  `aria-describedby`), never colour alone.
- **Status never colour-only** — `StockBadge`, `OrderStatusBadge`, cart line states,
  `PaymentRow` selection: each pairs colour with text and/or an icon/shape.
- **Selection is never colour-only** (`PaymentRow` = border + radio + tint + check).
- **Keyboard-accessible dialogs/sheets/drawers** — focus in → trap → `Esc`/scrim →
  focus returns to the trigger.
- **Reduced motion respected** everywhere (§13).
- **Meaningful image `alt`** strategy: real product images get a descriptive alt
  (product + notable variant); the neutral placeholder frame is decorative (`alt=""`)
  with the product name already visible as text nearby.
- **Logical DOM / reading order** — two-column desktop layouts are CSS placement only;
  the DOM order matches the mobile reading order.

## 19. Design-change governance

After **DESIGN APPROVED**, implementation phases **must not casually change**:

- Primary colour · accent use · type scale · radius language · shadow language ·
  container width · `ProductCard` · the header system · the checkout visual model ·
  mobile navigation · primary-CTA hierarchy.

**If implementation exposes a real issue**, it is raised as a **Design Deviation
Proposal** before any global rule changes — documenting:

```
Design Deviation Proposal
- Current rule:      (quote the frozen rule, with section #)
- Problem:           (what real content/behaviour breaks it)
- Proposed change:   (the minimal fix)
- Affected screens:  (every screen touched)
- Accessibility impact: (contrast / target-size / motion consequences)
```

Approved changes are folded back into this document (a dated addendum), never silently
patched in code. **Two changes are pre-flagged as likely candidates for this process:**
the product-image aspect ratio (§2.5/§11, pending the real-image checkpoint) and the
exact brand blue/pink (§4, pending the real logo asset).
